# Documentation

The working documents behind these filters — kept on purpose, so the process is as visible as the product. These are the *original* planning and design files, not write-ups made after the fact.

| Document | What it is |
|---|---|
| [design-spec.md](design-spec.md) | The day-one design: goal, product direction, architecture, and phased scope — written **before** any code. |
| [implementation-plan.md](implementation-plan.md) | The task-by-task build plan, with checkboxes tracking each step as it was completed. |
| [brand-direction.md](brand-direction.md) | Brand family, visual direction, icon concepts, and shared palette. |
| [../PROJECT_STATUS.md](../PROJECT_STATUS.md) | Live status, task history, and a dated decision log. |

**How these filters were built:** I define the product and its scope, write the spec and plan, drive the implementation with AI tooling, keep everything under version control, and log decisions and fixes as I go. The trail above is that method in practice.

`images/` holds the demo GIFs, logo, and product icons used across the READMEs.
